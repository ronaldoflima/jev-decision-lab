Uma rodada do experimento

O código calcula as ações legais e descreve o estado atual. A avaliação desse estado é feita pelo Jev através da Decisions API do OpenRouter. A resposta estruturada volta ao código, que aplica a escolha e prepara a próxima rodada.

O código executa; o Jev escolhe. O modelo não altera o mapa nem executa comandos no computador. Retorna uma das alternativas fornecidas para um entregador fictício.

Como foi feita a chamada HTTP

As chamadas registradas usaram um adaptador HTTP Python com httpx. O executor público desta versão usa fetch nativo do Node.js para enviar o mesmo contrato diretamente ao OpenRouter.

POST https://openrouter.ai/api/alpha/decisions Authorization: Bearer <chave OpenRouter> Content-Type: application/json { "model": "typesafe/jev-1.13", "state": ..., "questions": ... }

A chave é fornecida por OPENROUTER_API_KEY no ambiente de execução; não é colocada no estado enviado ao modelo ou nos HTMLs. O modelo resolvido nos registros foi typesafe/jev-1.13-20260917.

Campo enviado à APIFunção

O que vai dentro da pergunta choice

Estado

  • Posição, tempo virtual, bateria e entregas realizadas.
  • Mapa conhecido, prazos e locais de recarga.
  • Eventos já observados e decisões recentes.
  • Saldo de desfazimentos e estados que cada opção recupera.

Pergunta

  • type: choice: selecionar uma alternativa.
  • instructions: objetivo e orientação da decisão.
  • criteria: mapa de identificadores para descrições das ações.
  • Nos testes de planejamento, dados e instruções foram enviados em inglês.

As chamadas são independentes. O histórico necessário é reenviado no estado; a continuidade da tarefa é mantida pelo simulador.

O que o Jev devolve

CampoComo foi usado
choiceAção escolhida. O simulador verifica se ela está entre as opções legais.
probabilitiesDistribuição das alternativas; registrada para análise.
confidenceConfiança retornada pelo modelo, sem recalculá-la nos testes de choice.
modelVersão resolvida pelo serviço.
usageTokens e custo reportado pela API.
A marcação de baixa confiança é local. O valor de confidence vem da API. O código compara esse valor com o limiar de 0,7 e acrescenta a indicação low_confidence. Esse limiar não é enviado ao modelo como um requisito para escolher.

Tags, identificador local de chamada, latência e hash do estado são metadados do registro. Os pedidos e resultados foram registrados para auditoria; não há outra chamada a um LLM para reescrever o estado, alterar a escolha ou elevar a confiança nessa implementação.

Quem controla as regras

O simulador calcula as alternativas antes de cada chamada e aplica a escolha retornada. Deslocamentos consomem tempo e bateria; entregar leva um minuto; recarregar leva três. O bloqueio futuro só entra no estado quando é observado.

Cada desfazer mostra o estado recuperado e consome tantos créditos quanto ações removidas. Posição, tempo, bateria, energia e entregas são restaurados. Custos, quantidade de decisões e conhecimento de eventos permanecem.

Os totais foram recuperados dos registros locais dos identificadores deste experimento e incluem as tentativas de geração e de planejamento. São custos retornados pela API, não uma conciliação de fatura. Não incluem voz, este assistente ou a criação dos artefatos.

O resultado final mostra recuperação neste cenário. Houve poucas execuções e diferentes instruções entre configurações, sem isolar o efeito de cada mudança.

Fontes e autoria do experimento

A implementação HTTP e os registros foram conferidos na VPS. O contrato da API também consta na documentação do OpenRouter sobre Jev. A TypeSafe documenta o modelo.

O cenário foi desenvolvido nesta conversa, com auxílio do Codex, e não foi adaptado de um benchmark específico. Os HTMLs podem ser apresentados offline.
